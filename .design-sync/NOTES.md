# Design Sync Notes — NotWallet

## Repo shape
- Application repo (Tauri + React), NOT a component library
- shape=package, tokens-only (componentSrcMap: {})
- Synthetic entry: `notwallet-ds-entry.ts` (hand-authored, not from a lib dist)
- Entry built manually via the esbuild JS API (the esbuild CLI binary is arm64, not directly shell-executable via `node` on this machine)

## Build quirks
- Tailwind colors come from `tailwind.config.js` — CSS custom properties were hand-authored into `notwallet-tokens.css` (not generated by Tailwind CLI)
- No MUI custom theme file exists; MUI is used with its default theme
- `guidelinesGlob: []` — excluded all docs because they're engineering implementation guides (iOS release, keystore, Solana, i18n), not design guidelines
- `--no-render-check` used (no playwright installed, and tokens-only DS has 0 component previews)

## Re-sync procedure
1. Re-copy staged scripts: `cp -r <skill-dir>/package-build.mjs ... .ds-sync/`
2. Re-install converter deps: `cd .ds-sync && npm i esbuild ts-morph @types/react`
3. Build entry (if token values changed): `node --input-type=module -e "import {build} from './.ds-sync/node_modules/esbuild/lib/main.js'; await build({entryPoints:['notwallet-ds-entry.ts'],bundle:true,format:'esm',outfile:'notwallet-ds-entry.js'})"`
4. Run converter: `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules ./node_modules --entry ./notwallet-ds-entry.js --out ./ds-bundle`
5. Validate: `node .ds-sync/package-validate.mjs ./ds-bundle --no-render-check`
6. Upload (atomic path on re-sync)

## Re-sync risks
- `notwallet-tokens.css` is hand-maintained — if Tailwind config colors change, update `notwallet-tokens.css` manually before re-syncing
- `conventions.md` naming section references Tailwind class names (`text-primary-main` etc.) — if Tailwind config keys change, update conventions.md too
- `notwallet-ds-entry.ts` tokens object mirrors the Tailwind config — same update rule
- No component previews: a future re-sync wanting to add components must handle Tauri API stubs (all `@tauri-apps/*` imports need browser-safe mocks) and app-specific React context providers (cfg.provider chain)
- render check was never machine-verified (tokens-only; accepted by user)
